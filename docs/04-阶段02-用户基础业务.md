# 阶段 02：用户基础业务

日期：2026-11-09。状态：代码完成、编译通过；未执行数据库迁移和运行联调。

## 1. 本次范围与参考

参考 qiyu-live 的 `IUserRpc` 中创建、查询、修改用户的职责划分，沿用 API → RPC → Provider → 数据库的调用方向。本阶段实现单用户基础业务，批量查询、缓存和登录在后续添加。

当前数据访问沿用工程已有的 JdbcTemplate，没有为三个基础操作增加新的依赖。数据库访问集中在 `UserRepository`，后续可替换为 Mapper 而不影响 RPC 契约。

## 2. 数据与分层

`sql/002-user.sql` 创建 `t_user`：

| 字段                      | 规则                                         |
| ----------------------- | ------------------------------------------ |
| id                      | BIGINT 自增；首版单库；对外 JSON 使用字符串               |
| nickname                | 去除首尾空白，1～32 个 Unicode 字符，禁止控制字符；允许重名       |
| avatar_url              | 最大 512 字符，HTTP/HTTPS 地址；允许空字符串；只保存地址，不抓取文件 |
| status                  | 1 正常、0 禁用；本阶段不开放状态修改接口                     |
| version                 | 初始 0，每次资料修改递增                              |
| created_at / updated_at | UTC DATETIME(3)，对外返回带 Z 的时间字符串             |

- `UserRpc / UserDTO / UserBusinessException`：接口包中的业务契约、传输对象和业务异常。
- `UserService`：参数校验、事务、状态判断；直接调用 RPC 也必须经过校验。
- `UserRepository / UserRow`：参数化 SQL 与持久化记录。
- `UserApplicationService`：调用 RPC，保留业务异常，将依赖故障映射为不可用。
- `DevUserController`：本地调试入口，只有 API 启用 `local` profile 时加载。

## 3. 并发修改设计

更新资料时携带查询结果中的 version。数据库执行带有 `id + version + status` 条件的更新，并在同一条 SQL 中递增 version。受影响行数为 0 时，区分用户不存在、用户禁用和版本冲突。

例如两个页面都读取 version=0，第一次修改成功后版本为 1，第二次仍提交 0 则返回 409。调用方重新读取后决定是否重新提交，服务端不自动覆盖新资料。

创建和修改均使用本地事务，保证更新后的查询发生在同一事务内。写 RPC 配置 retries=0，避免框架自动重试创建操作；创建请求本身尚未幂等，网络超时后不能盲目重复创建。登录阶段会通过手机号唯一约束及注册流程补充账号防重。

本阶段没有引入 Redis 锁。资料更新已有数据库版本约束，后续热点缓存重建再单独引入互斥锁。

## 4. 数据库部署

全新 MySQL 数据卷会按 Compose 挂载自动执行 001 和 002 脚本。已有数据卷不会自动执行新增 SQL，需从项目根目录手动执行：

```powershell
docker compose --env-file deploy/.env -f deploy/compose.yaml cp sql/002-user.sql mysql:/tmp/002-user.sql
docker compose --env-file deploy/.env -f deploy/compose.yaml exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_PASSWORD" mysql -u live_app live_platform < /tmp/002-user.sql'
```

也可通过数据库工具连接 13306 端口，在 `live_platform` 库执行 `sql/002-user.sql`。脚本不删除已有数据；`IF NOT EXISTS` 只处理首次建表，不会迁移已有的不同表结构。无需删除或重建数据卷。

## 5. 编译、启动和接口

```powershell
mvn -f backend/pom.xml -DskipTests package
```

先按 README 设置 MYSQL_PASSWORD 并启动用户服务，再启动 API：

```powershell
java -jar backend/live-api/target/live-api-0.1.0-SNAPSHOT.jar --spring.profiles.active=local
```

这些指定用户 ID 的接口目前没有登录鉴权，仅用于本地开发。正常部署不启用 local；后续登录阶段通过认证身份提供“我的资料”接口。HTTP 默认继续绑定 127.0.0.1。

| 请求 | 输入 | 成功 |
| --- | --- | --- |
| POST `/api/dev/users` | nickname、avatarUrl | 201，返回新用户 |
| GET `/api/dev/users/{id}` | 正整数 ID | 200，返回用户资料与 version |
| PUT `/api/dev/users/{id}/profile` | nickname、avatarUrl、version | 200，返回更新后的资料 |

PUT 表示完整替换可编辑资料，nickname 必填；avatarUrl 为 null、空或省略时清空头像。不能修改 ID、状态、创建时间。读取禁用用户返回其状态，修改禁用用户返回 403。

错误语义：400 参数或 JSON 格式错误，404 用户不存在，403 用户禁用，409 版本冲突，503 RPC 或数据库不可用。统一返回 code、message、data、requestId。

可直接使用 `scripts/users.http`，将创建结果的 ID 填入 userId。更新时传最近一次查询的 version。
